LONGLIVY — BACKEND API REQUIREMENTS
====================================
For: LongLivy backend developer
Base URL: https://longlivy.digitallhut.com/api/v1
Prepared: 2026-10-08, from live testing of the deployed API and the mobile app source.

Everything below is what the mobile app still needs from the backend. Each item
was checked against BOTH the API document (docs/API_DOC.txt, 84 endpoints) and
the live server before being listed: it is either absent from the document and
returns 404, or it is documented but behaves incorrectly on the server.
Existing endpoints that already satisfy a need are NOT re-proposed; where an
existing endpoint needs a change, the item says "CHANGE TO EXISTING ENDPOINT".

Summary (after removing duplicates of existing endpoints):
  29 required new endpoints + 2 optional, 13 changes to existing endpoints,
  1 infrastructure fix. Item numbers are stable IDs (other reports cite them);
  withdrawn items keep their number.

1. DELETE /auth/account
=====================================================================
MODULE: Auth & Account
FEATURE: "Delete my account" (Privacy screen) — required by Apple App Store
         Guideline 5.1.1(v) and Google Play for apps with account creation;
         also GDPR Art. 17.
API NAME: Delete account
PURPOSE: Permanently delete the authenticated user and all their data.
PRIORITY: P0

METHOD: DELETE
ENDPOINT: /auth/account
AUTHENTICATION REQUIRED: Yes
HEADERS: Authorization: Bearer <token>, Accept: application/json, Content-Type: application/json

QUERY PARAMETERS: none
PATH PARAMETERS: none

REQUEST BODY:
{
  "password": "string, required — re-authentication",
  "confirmation": "DELETE"
}

SUCCESS RESPONSE: HTTP 200
{
  "success": true,
  "message": "Account deleted.",
  "data": { "deleted_at": "2026-10-08T12:00:00+00:00" }
}

ERROR RESPONSE:
  HTTP 422 { "message": "The password is incorrect.", "errors": { "password": ["The password is incorrect."] } }
  HTTP 422 { "message": "Type DELETE to confirm.", "errors": { "confirmation": ["Type DELETE to confirm."] } }

STATUS CODES: 200, 401, 422, 429
VALIDATION RULES:
  password: required|string|current_password
  confirmation: required|in:DELETE
  Throttle: 5 attempts / minute / user.
DATABASE REQUIREMENTS:
  Hard-delete (or anonymise within 30 days) user, profile, tokens, weight_logs,
  fastings, meals, meal_items, foods (custom), recipes, recipe_items,
  favorites, goals, goal_progress, streaks, meditation_sessions,
  meditation_reminders, devices, notifications. Revoke all Sanctum tokens.
FRONTEND USAGE: src/screens/home/PrivacyScreen.tsx:35 ("Delete my account" is
  currently a no-op). Data management screen will call it too.
DEPENDENCIES: none

2. POST /auth/forgot-password
=====================================================================
MODULE: Auth & Account
FEATURE: Forgot password
API NAME: Request password reset
PURPOSE: Email a reset code/link. Always responds the same way so it cannot be
         used to discover which emails have accounts.
PRIORITY: P0

METHOD: POST
ENDPOINT: /auth/forgot-password
AUTHENTICATION REQUIRED: No
HEADERS: Accept: application/json, Content-Type: application/json

REQUEST BODY:
{ "email": "user@example.com" }

SUCCESS RESPONSE: HTTP 200 (also for unknown emails)
{ "success": true, "message": "If an account exists for this email, a reset code has been sent." }

ERROR RESPONSE:
  HTTP 422 { "message": "The email field must be a valid email address.", "errors": { "email": ["..."] } }
  HTTP 429 { "message": "Too many requests. Try again in 60 seconds." }

STATUS CODES: 200, 422, 429
VALIDATION RULES: email: required|email:rfc|max:255. Throttle 3 / 15 min / email+IP.
DATABASE REQUIREMENTS: password_reset_tokens (email, token hash, created_at). Token TTL 60 min, single use.
FRONTEND USAGE: src/screens/auth/ForgotPasswordScreen.tsx (calls
  authRepository.resetPassword -> currently rejects "Password reset is not available yet").
DEPENDENCIES: transactional email (SMTP/SES/Postmark).

6. GET /meditation and GET /meditation/{id} — POPULATE CONTENT + AUDIO FIELDS
   (CHANGE TO EXISTING ENDPOINT)
=====================================================================
MODULE: Meditation
FEATURE: Meditation library, details, player
API NAME: Meditation content catalog
PURPOSE: Serve real meditation content with streamable audio, so the app can
         stop shipping 17 bundled MP3 files.
PRIORITY: P1

CURRENT BEHAVIOUR: GET /meditation -> { "data": { "meditations": [] } };
  GET /meditation/{id} -> 404 for every id; GET /meditation/categories -> [].
  The app therefore falls back to its bundled catalog.

METHOD: GET
ENDPOINT: /meditation        and        /meditation/{id}
AUTHENTICATION REQUIRED: Yes
HEADERS: Authorization: Bearer <token>, Accept: application/json

QUERY PARAMETERS (list) — keep the documented ones and add paging:
  type          optional  guided|free|breathing|individual   (documented)
  category      optional  category slug                        (documented)
  language      optional  en|de                                 (documented)
  max_duration  optional  minutes                               (documented)
  q             optional  search                                (documented)
  page          optional  integer >= 1 (see #25)               (new)
  per_page      optional  integer 1..100, default 50            (new)
PATH PARAMETERS: id — integer

SUCCESS RESPONSE (list): HTTP 200
{
  "success": true,
  "message": "Meditations retrieved successfully.",
  "data": {
    "meditations": [ <Meditation> ],
    "meta": { "current_page": 1, "per_page": 50, "total": 23, "last_page": 1 }
  }
}
SUCCESS RESPONSE (single): HTTP 200
{ "success": true, "message": "Meditation retrieved successfully.", "data": { "meditation": <Meditation> } }

<Meditation> — exact fields (required unless marked nullable):
{
  "id": 12,                                   integer
  "title": "Deep Relaxation",                 string
  "description": "Full-body relaxation ...",  string
  "type": "guided",                           guided|free|breathing
  "category": { "id": 3, "slug": "relaxation", "name": "Relaxation" },
                                              slug one of: morning, mindfulness, energy,
                                              focus, relaxation, calm, stress_relief, sleep
  "sound_category": null,                     nullable; for type=free: meditation_music|ambient|nature
  "language": "en",                           en|de
  "duration_seconds": 900,                    integer
  "thumbnail_url": "https://cdn.longlivy.app/meditations/12/thumb@2x.jpg",   nullable, https
  "audio": {                                  nullable ONLY while the item is coming soon
    "url": "https://cdn.longlivy.app/meditations/12/en/audio.m4a?Expires=...&Signature=...",
    "format": "m4a",                          mp3|m4a|aac
    "mime_type": "audio/mp4",
    "bitrate_kbps": 128,
    "duration_seconds": 900,
    "size_bytes": 14400000,
    "is_streamable": true,
    "expires_at": "2026-10-08T18:00:00+00:00" nullable (null = public URL)
  },
  "availability": "available",                available|coming_soon
  "is_premium": false,
  "is_favorite": false,                       per-user (from /favorites)
  "version": "1.0",
  "updated_at": "2026-10-01T09:00:00+00:00"
}

ERROR RESPONSE: 404 { "success": false, "message": "Meditation not found." }
STATUS CODES: 200, 401, 404
VALIDATION RULES: query params validated; unknown type/category -> 422.
DATABASE REQUIREMENTS:
  meditations(id, title, description, type, category_id, sound_category,
    duration_seconds, thumbnail_path, availability, is_premium, status
    draft|published|archived, version, timestamps)
  meditation_audio(id, meditation_id, language, storage_path, format,
    mime_type, bitrate_kbps, duration_seconds, size_bytes)
    unique(meditation_id, language)
  meditation_categories(id, slug, name_en, name_de, sort_order)
  Only status=published rows are returned.
FRONTEND USAGE: src/services/api/meditationApi.ts (mapMeditationContent already
  reads exactly these fields), MeditationHomeScreen, MeditationCategoriesScreen,
  MeditationDetailsScreen, MeditationPlayerScreen.
DEPENDENCIES: object storage + CDN (S3/R2/Bunny), content upload in admin.

   (CHANGE TO EXISTING ENDPOINT; previously proposed as a new route)
=====================================================================
PRIORITY: P2
MODULE: Meditation
FEATURE: Resume interrupted playback; accurate listening statistics
NOTE: The documented PUT /meditation/sessions/{session} accepts only "notes".
  Extend it with the fields below instead of adding a new route.

METHOD: PUT
ENDPOINT: /meditation/sessions/{session}   (existing route, new fields)
AUTHENTICATION REQUIRED: Yes
HEADERS: Authorization: Bearer <token>, Accept: application/json, Content-Type: application/json
PATH PARAMETERS: id — meditation session id (integer)

REQUEST BODY:
{
  "position_seconds": 312,          integer >= 0, required
  "active_seconds": 300,            integer >= 0, required (time actually played)
  "paused_seconds": 45,             integer >= 0, required
  "client_timestamp": "2026-10-08T11:31:12+00:00"   required
}

SUCCESS RESPONSE: HTTP 200
{ "success": true, "message": "Progress saved.",

STATUS CODES: 200, 401, 403, 404, 422

  Client calls every 15 s while playing + on pause/background. Rate limit 10/min/session.
DATABASE REQUIREMENTS: meditation_sessions add position_seconds int, active_seconds int, paused_seconds int, progress_updated_at timestamp.
  GET /meditation/sessions/active must return these fields.

  the app edits them with PUT /goals/{id}.

PROBLEMS:
  a) A manual edit (PUT /goals/{id} { "target_value": 140 }) keeps

  b) Recalculating overwrites manual targets: after the edit above,
     POST /energy/targets/calculate set protein back to 157.95 ("updated": true).

  c) The nutrition_* goal types are not in the document. Document them and the
     calculation (Mifflin-St Jeor TDEE, adjustment -500/0/+500, macro split).
  d) The direction is fixed at ±500 kcal. The app lets users pick a weekly pace
     (0.25–1.0 kg/week). Accept an optional
     "weekly_change_kg": 0.5 (adjustment = weekly_change_kg * 7700 / 7).

FRONTEND USAGE: src/services/api/nutritionTargetsApi.ts,
